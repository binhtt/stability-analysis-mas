# Analyzing Feedback Stability of Evolving Multi-Agent Systems

Python code, archived configurations, raw results, numerical validation, and figures for stability screening of evolving periodic positive systems. No manuscript or LaTeX source is included or generated by the analysis scripts.

## Quick start

Python 3.12 was used for the recorded experiments. No GPU, LLM API, or external dataset is required.

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python reproduce.py --mode summaries
python reproduce.py --mode checks
```

Windows PowerShell activation: `.venv\Scripts\Activate.ps1`.

The default `summaries` mode reads archived results and regenerates summary CSVs and plots. It does not rerun timings or candidate generation.

```bash
python reproduce.py --mode baseline   # main, duration, cache, independent seed
python reproduce.py --mode evolution  # sequential, topology, profiling, numerical audits
python reproduce.py --mode all        # both suites
```

Full runs overwrite outputs within each study directory. Copy the archive before rerunning if you need the recorded values. Child processes use one BLAS thread. Timing and nominal-boundary calibration can vary by platform.

## Layout

- `studies/baseline/`: original main study and complementary duration, cache, and independent-seed assessments.
- `studies/evolution/`: successive-version chains, diverse kernels up to 768 agents, cost profiling, and numerical boundary audits.
- `RESULTS.md`: interpretation and main recorded findings.
- `RESULT_INDEX.md`: raw/configuration/summary mapping and reproduction commands.
- `MANIFEST.sha256`: hashes of packaged files; regenerated after packaging, not by study scripts.

Raw files remain beside their scripts to preserve relative-path assumptions. Study-specific metadata and logs document recorded runs. Source files named `baseline_core.py` and `cache_core.py` in the evolution suite are self-contained snapshots of the screening primitives; they do not import a separate checkout.

## Experimental design

| Assessment | Units | Location |
| --- | ---: | --- |
| Main | 3,600 cases | baseline |
| Duration | 1,800 evaluations | baseline |
| Independent seed | 1,800 cases | baseline |
| Successive versions | 1,440 versions in 36 chains | evolution |
| Topology and size | 216 cases, up to 768 agents | evolution |
| Cost decomposition | 81 cases | evolution |
| Boundary controls | 162 controls, five guards | evolution |

The duration study repeats 450 main-study cases at period 4. Methods, timing repeats, guard variants, and cache reanalyses are not independent samples. Successive updates within a chain are dependent. Original groups are reported separately from calibrated stress groups.

Evolution-suite seeds: sequential 2026110101; topology 2026110102; profiling 2026110103; numerical 2026110104; bootstrap 2026110105. Designs and configurations are included as JSON.

## Numerical interpretation

Stable/unstable/unknown outcomes concern the supplied periodic dynamical model. Float64 guard bands are not rounding-error certificates. High-precision spectral estimates and interval actions are distinct checks. Interval validation treats the supplied binary64 parameters as exact real inputs, without measurement uncertainty. The zero-guard witness replay is post hoc; calibration at a nominal zero growth target may leave a small signed residual that changes across platforms. Review regenerated results rather than assuming archived mismatch counts must recur.

The model retains two populations, nonnegative cross-population kernels, positive losses, and a prescribed periodic schedule. Successive-version analysis does not establish stability during arbitrary switching, behavioral correctness of executable agents, or deployment safety.
